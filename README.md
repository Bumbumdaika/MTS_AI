# Energytool — часть Ивана: сбор заявки и память диалога

Дополненная версия исходного проекта. Реализованы пункты 4 и 5: сбор ФИО,
телефона и компании, краткое резюме обращений, сохранение заявки, история
одного диалога и кнопка «Новый диалог». Исходные поисковые эксперименты сохранены.

## Быстрый запуск на Windows

Нужен Python 3.10 или новее. Распакуйте архив, откройте терминал в папке проекта:

```powershell
python server.py
```

Если команда `python` не найдена, используйте `py server.py`.
Откройте http://127.0.0.1:8000 . Для остановки нажмите Ctrl+C в терминале.
По умолчанию работает демонстрационный режим без установки библиотек, ключей
и скачивания моделей. Он находит тексты по словам и показывает их пользователю;
полноценная генерация LLM включается отдельно.

Консольный вариант: `python solution.py`.
Проверки: `python -m unittest discover -s tests -v`.

## Как проверить свою часть на защите

1. Напишите «Интересует мониторинг оборудования на заводе».
2. Перейдите к другой теме: «А что с анализом расходов?».
3. Нажмите «Связаться с менеджером».
4. Введите ФИО. Попробуйте некорректный телефон: `123` — бот попросит исправить.
5. Во время сбора напишите `/ask Вернёмся к мониторингу оборудования`.
   Бот ответит и продолжит запрашивать телефон. Вопросы со знаком `?` также
   распознаются как консультация. Для неоднозначных фраз используйте `/ask`.
6. Введите телефон с кодом страны, затем компанию.
7. Бот покажет контакты и краткое резюме обращений. Нажмите «Подтвердить заявку».
8. Обновите страницу — диалог восстановится. Перезапустите сервер — данные сохранятся.
9. Нажмите «Новый диалог» — история и поля нового диалога пустые.
   Старые заявки сохраняются. Два отдельных окна/вкладки получают разные сессии
   при независимом открытии; дублирование вкладки браузером может скопировать sessionStorage.

Резюме формируется автоматически из последних восьми консультационных обращений
пользователя (до 350 символов каждое). Это сокращённая выдержка потребностей,
а не генеративное резюме LLM. Контактные ответы из сценария заявки туда не входят.
Если консультации не было, отмечается, что потребности пока не уточнены.

## Настройка настоящей LLM

Скопируйте `.env.example` в `.env`. Укажите выданные командой/организаторами настройки:

```dotenv
BOT_MODE=llm
SEARCH_BACKEND=basic
LLM_BASE_URL=https://АДРЕС-ПРОВАЙДЕРА/v1
LLM_API_KEY=ВАШ-КЛЮЧ
LLM_MODEL=НАЗВАНИЕ-МОДЕЛИ
```

Код отправляет POST на `{LLM_BASE_URL}/chat/completions`.
Используется совместимый формат сообщений; конкретный провайдер должен его поддерживать.
Значения в `.env.example` — заглушки. Настоящие ключи в архив не включены.
Перезапустите сервер после изменения настроек. Переменные окружения имеют приоритет над `.env`.
В LLM передаются документы, последние 30 консультационных сообщений и короткие
выдержки более ранних вопросов для возвращения к старым темам. Контактные ответы
сценария заявки исключаются. API-ошибка не превращается в выдуманный ответ: интерфейс
предлагает повторить запрос. Вопросы по продукту могут передаваться провайдеру LLM.

## Подключение исходного BGE-M3

Для семантического поиска установите зависимости:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python bge_search.py
```

Первый запуск скачивает модель и требует доступа к её хранилищу.
После создания индекса завершите поиск словом `exit`.
Укажите `SEARCH_BACKEND=bge` в `.env` и запускайте:

```powershell
.venv\Scripts\python server.py
```

BGE загружается при запуске сервера один раз. Для четырёх документов FAISS не нужен;
исходный `faiss_search.py` на самом деле считает сходство NumPy.
Гибридный поиск сохранён как эксперимент, сервер его не использует.
Базовый поиск — простой лексический baseline, без морфологии русского языка;
он предназначен для проверки сценария и подключения компонентов.

## Где хранятся заявки

SQLite-файл `runtime/bot.sqlite3` создаётся автоматически. Он содержит историю,
контакты и заявки. `BOT_DB` позволяет задать другой путь. Одна заявка на диалог;
повторное подтверждение не создаёт дубликат. Новая заявка — новый диалог.
Отмена `/cancel` прекращает сбор, но уже написанные сообщения остаются в истории.

Автоматическая отправка в CRM, почту или мессенджер не подключена. Сохранённые
заявки можно выгрузить локально для менеджера:

```powershell
python export_leads.py --output leads.csv
```

CSV содержит персональные данные. Экспорт экранирует значения, которые табличные
редакторы могут интерпретировать как формулы. Публичного API для списка заявок нет.

## Подключение к интерфейсу команды

| Действие | Запрос | Ответ |
|---|---|---|
| Новый диалог | `POST /api/sessions`, JSON `{}` | `id`, `history`, `stage`, `fields`, `lead_id` |
| Сообщение | `POST /api/chat`, JSON `{"message":"..."}` | Обновлённое состояние диалога |
| Восстановление | `GET /api/session` | Состояние текущего диалога |
| Проверка сервера | `GET /api/health` | Режим `demo` или `llm` |

Для сообщений и восстановления передавайте заголовок
`Authorization: Bearer <id из POST /api/sessions>`.
Идентификатор — секрет доступа к одному диалогу. Не передавайте его другим людям.
Интерфейс хранит его в `sessionStorage`, не в URL.
Кнопка «Новый диалог» создаёт новую сессию и переключает интерфейс на её ID.
При нажатии «Связаться с менеджером» отправляется `/lead`, подтверждении — `/confirm`,
отмене — `/cancel`. Повторный `/lead` до сохранения позволяет заполнить контакты заново.
Исключение: если заявка уже сохранена, сервер возвращает её номер.

```javascript
const state = await fetch('/api/sessions', {
  method: 'POST', headers: {'Content-Type': 'application/json'}, body: '{}'
}).then(r => r.json());
const next = await fetch('/api/chat', {
  method: 'POST',
  headers: {'Content-Type': 'application/json', 'Authorization': 'Bearer ' + state.id},
  body: JSON.stringify({message: 'Интересует мониторинг оборудования'})
}).then(r => r.json());
console.log(next.history.at(-1).content);
```

## Файлы для вашей команды

- `dialogue.py` — логика пунктов 4 и 5, валидация, переходы состояний, резюме.
- `storage.py` — SQLite: диалоги и заявки, атомарное сохранение.
- `solution.py` — связка поиска, генератора и диалогов; консольный запуск.
- `rag_generator.py` — исходный генератор с добавлением истории (исправлено двойное `.py`).
- `retrieval.py` — простой поиск без зависимостей или адаптер исходного BGE.
- `server.py`, `web/index.html` — локальный API и интерфейс для демонстрации.
- `export_leads.py` — локальная CSV-выгрузка.
- `tests/test_workflow.py` — автоматические проверки.

## Границы готовности

Это локальный однопроцессный прототип для хакатона. Сервер привязан к 127.0.0.1;
для публичного развёртывания нужен отдельный сервер приложения, HTTPS, управление
доступом операторов и политика хранения данных. Запросы к диалогу сериализуются
внутри процесса: медленный ответ LLM задерживает обработку других сообщений.
История ограничена 400 сообщениями (примерно 200 обменов), затем требуется новый диалог.
Проверка телефона проверяет формат, а не существование номера; код страны должен
ввести пользователь. Потребность связаться с менеджером распознаётся по некоторым
явным фразам, а кнопка заявки доступна постоянно.

Исходная база содержит только четыре общих текста. Для содержательных консультаций
команде нужно дополнить `data/knowledge.json` проверенными материалами продукта.
API LLM и загрузка BGE с реальным провайдером в этой среде не проверялись.
Автоматические проверки используют заглушку LLM для проверки состава сообщений.
